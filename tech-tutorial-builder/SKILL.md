# 技术栈交互式学习包生成器

为单个技术栈生成统一风格、高质量的学习包：**交互式 HTML 教程 + 知识点示例 + 实战项目**，最后打包成 zip 供用户下载到本地。

这个 skill 把一套经过打磨的教学设计沉淀下来，让每个技术栈的产出都遵循同样的节奏与质量标准，用户可以快速学习任意新技术栈。

## 何时使用

用户想系统学习某个技术栈，或想要一份某语言/框架/工具的教学材料时使用。一次处理一个技术栈；如果用户报了多个（如"Rust、Go、Python"），逐个产出，每完成一个询问是否继续下一个。

## 总体产出结构

每个技术栈生成一个 `learn/<技术栈>/` 目录：

```
learn/
└── <技术栈名>/
    ├── index.html       # 交互式教程（浏览器打开即用，自包含）
    ├── examples/        # 知识点示例，每个概念一个文件
    │   ├── 01_<概念>.<ext>
    │   └── ...
    └── project/         # 实战项目（可运行）
        ├── README.md
        └── <按各语言惯例的源码结构>
```

## 工作流程

按顺序执行四步，**完成一步再做下一步**：① HTML 教程 → ② 示例文件 → ③ 实战项目 → ④ 验证并打包交付。

### 步骤 0：确定技术栈与实战主题

如果用户没指定实战项目主题，选一个能串起该技术栈核心知识点的实用项目（避免玩具示例）。参考主题：命令行工具、Web API、数据处理管道、状态管理应用、部署编排等。先用一句话和用户确认技术栈 + 实战主题，再开工。

创建目录：`mkdir -p learn/<技术栈>/examples learn/<技术栈>/project`

### 步骤 1：交互式 HTML 教程（index.html）

这是学习包的核心。**必须先阅读 `references/html-template-guide.md`** 了解完整的结构规范、CSS 设计系统、每个知识点的固定教学节奏、以及所有内联 JS（复制按钮、测验、滚动监听）。

教程由这些部分组成：固定左侧边栏（含自绘 SVG logo + 章节导航）+ 顶部进度条 + Hero 区 + 总览章节（00）+ 8-11 个知识点章节 + 最后的实战章节。

每个知识点章节遵循固定节奏：**生活化类比 → 概念说明 → SVG 图示 → 可折叠代码示例 → 交互测验**（测验可选）。

由于 HTML 文件很长（约 1000-1350 行），用追加方式分批写入避免单次过大：先 `create_file` 写入「头部 + 样式 + 侧边栏 + Hero + 总览」，再用 `cat >> ... << 'HTMLEOF'` 分批追加章节，最后追加实战章节 + highlight.js 引入 + 内联 JS + 闭合标签。

### 步骤 2：知识点示例文件（examples/）

每个核心知识点一个独立文件，文件名形如 `01_概念.ext`、`02_概念.ext`。每个文件：

- 文件头注释注明：知识点、学习目标、运行方式、依赖
- 详尽的行内注释，聚焦单一知识点
- 尽量自包含、可直接运行

数量与教程的知识点章节对应（通常 7-11 个）。

### 步骤 3：实战项目（project/）

遵循该语言的社区惯例组织目录（见 `references/stack-conventions.md`），让代码能真正运行：

- 目录结构符合语言惯例（Rust 用 `src/`、Go 扁平、Python 用包目录、Node 分层、前端框架用 `src/` + 构建配置等）
- `README.md` 用一个表格列出「知识点 ↔ 项目中的体现」对应关系，并写明运行说明
- 代码可运行，串联起教程教的多个知识点

### 步骤 4：验证、打包、交付

**先阅读 `references/verification-and-packaging.md`** 了解针对不同技术栈的验证策略和打包交付的完整流程。

核心要点：
- 能在沙箱运行的（如 Python/Node/TypeScript/前端框架）：实际编译/运行/构建来验证
- 不能运行的（缺编译器或网络受限，如可能的 Rust/Go/Helm）：人工语法审校
- 配置类（K8s/Docker 等）：用解析器校验语法（如 Python 的 `yaml` 库）+ 人工审校
- 报告时如实说明验证情况与任何环境限制
- 清理构建产物（node_modules、dist、__pycache__ 等）后打包成 `learn_tutorials.zip`，复制到输出目录，用 `present_files` 交付
- 若沙箱无法写用户本地路径，明确告知用户下载 zip 后解压到目标路径，并给出解压命令

## 复用到多个技术栈

这个 skill 维护一个累积的 `learn/` 目录和一个顶层 `learn/README.md`（索引表格）。每新增一个技术栈：把新模块加入 `learn/`，更新顶层 README 表格，重新打包整个 `learn/` 为一个 zip。这样用户最终得到一个包含所有已学技术栈的合集。顶层 README 的格式见 `references/verification-and-packaging.md`。

## 质量标准

- 教学节奏一致：每个知识点都走「类比→概念→图示→代码→测验」
- 视觉统一但各有特色：用该技术栈的官方主题色 + 暗色背景，侧边栏放自绘 SVG logo
- 类比要贴切生动，帮助建立直觉，而非套话
- 代码示例真实、可运行、注释详尽
- SVG 图示用于表达关系/结构/流程（如数据流、组件树、架构图），不是装饰
- 实战项目有真实价值，能让学习者把知识点串起来用
